# SQL-міграції — правило курсу (обов'язкове з Лабораторної 2)

Схема бази еволюціонує **лише вперед, новими файлами**:

- первинна схема (експорт вашої діаграми з drawDB) — **`001_initial.sql`**;
- **кожна** подальша зміна схеми — у наступних лабораторних і в курсовій —
  це **новий файл**: `002_add_loans_status.sql`, `003_rename_member_phone.sql`, …
- **редагувати чи видаляти вже застосований файл заборонено** — так само,
  як не можна переписати минуле в реальній базі, що вже працює у людей.

Іменування: `NNN_коротка_назва_латинкою.sql` (три цифри, snake_case).
Застосування з нуля — всі файли по порядку:

```bash
for f in sql/[0-9]*.sql; do
  docker compose exec -T db psql -U postgres -d myproject -v ON_ERROR_STOP=1 < "$f"
done
```

Перевіряється автоматично: `bash checks/run.sh` → `migrations` — іменування,
порядок номерів, незмінність файлів відносно попереднього тега `labN`
і (локально, з Docker) застосовність усього ланцюжка в чисту БД.
